# 测试策略

**最后更新**: 2026-03-11

## 当前测试现状

| 端 | 测试文件数 | 覆盖率 |
|----|-----------|--------|
| 后端（Java） | 5 | 极低（< 1%） |
| 前端（Vue.js） | 0 | 0% |

## 目标（adopt Phase 3）

建立安全网，覆盖所有已有功能，全部测试跑通全绿。

## 测试分层

### 后端

| 层次 | 工具 | 内容 |
|------|------|------|
| API 契约测试 | JUnit 5 + MockMvc | 每个端点：HTTP 方法/路径/状态码/响应结构 |
| 业务逻辑测试 | JUnit 5 + Mockito | 从 behaviors.md 的 Given-When-Then 转化 |
| 集成测试 | Spring Boot Test | 跨 Service 关键业务流程 |

### 前端

| 层次 | 工具 | 内容 |
|------|------|------|
| API Service 测试 | Jest + axios-mock | 每个 service 函数调用正确端点 |
| 组件测试 | Vue Test Utils | 关键交互和状态变化 |

## 关键约束

- 测试验证**行为**，不测实现细节
- 测试数据自包含，不依赖外部状态
- Facade 端点需加严格结构断言（向下兼容保证）
